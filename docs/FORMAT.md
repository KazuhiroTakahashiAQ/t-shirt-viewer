# Tfas (.tfs) ファイル形式メモ

Tfas の図面ファイルを、サンプル 119 ファイルの解析から読み解いた結果です。公式仕様ではありません。「確認済」は全サンプルで矛盾がないもの、「推定」は統計やプレビュー画像との照合による推定です。数値はすべてリトルエンディアン。

## 1. ファイル全体

| オフセット | 内容 |
| --- | --- |
| 0x00 | `"TFAS"` |
| 0x08 | u8 メジャー (3), u8 フラグ (0x80 = 64bit セクション表), u8, u8 マイナー (4〜6) |
| 0x40 | 20 バイトのダイジェスト |
| 0x58 | セクション表。各エントリ (開始, 終了) のファイルオフセット。32bit 形式は i32×2 を 0x148 まで (30 個)、64bit 形式は i64×2 を 0x458 まで。-1 は未使用 |

主なセクション (番号はセクション表のインデックス):

| No. | 内容 |
| --- | --- |
| 0 | ファイル情報 (作成元パス、編集履歴。履歴文字列は各バイト XOR 0x0F) |
| 1 | 文書設定。レコード 1: 縮尺、レコード 2: 用紙範囲、zlib ブロック内に図形属性表など |
| 3 | 部品 (シンボル) 定義 |
| 4 | 図形本体。シートごとに 1 つの zlib ブロック |
| 5 | プレビュー。レコード 9: 100×100 DIB、レコード 0x25: u32 1, u32 長さ + 800×800 PNG |
| 8, 10, 13, 14 | 印刷・文字/寸法スタイル・設備設定など (未使用) |
| 24 | レイアウト一覧と文字関数 (レコード 1: u32, u32 長さ + CP932 の XML)。下記 |

## 2. レコード

セクションの中身はレコードの列です。

```
u32 size   (ヘッダ 8 バイトを含む)
u16 type
u16 section id (セクション番号 + 1)
...        本体
```

- セクション直下のレコードは 8 バイト境界に揃えられる。zlib ブロック内のレコードは詰めて並ぶ。
- type に 0x2000 または 0x4000 が立ち、本体が `78 ..` で始まるものは zlib ストリーム。展開するとレコード列が現れる (0x4002 は空の終端)。

## 3. タグ付き値ストリーム

多くのレコード本体は 1 バイトのタグ + 値の列です (タグは 5 の倍数)。

| タグ | 値 |
| --- | --- |
| 0x05 / 0x0A | リスト開始 / 終了 |
| 0x0F | u32 長さ + バイト列 |
| 0x14 | u8 |
| 0x19 | i16 |
| 0x1E | i32 |
| 0x2D | f64 |

## 4. 文書設定 (セクション 1)

- レコード 1: `u32×4` の後に f64 (1/縮尺)、f64 (縮尺の分母)。例: 1/50 なら 0.02, 50.0。
- レコード 2: f64×4 で用紙範囲 (x0, y0, x1, y1、モデル座標)。A1・1/50 なら 0〜42050 × 0〜29700。
- zlib ブロック内レコード 0x1001: 図形属性表 (後述)。

座標系: すべての図形は「用紙 mm × 文書縮尺」のモデル座標で保存されています。縮尺が異なるシート (1/10 の詳細図など) も同じ座標系に置かれ、座標変換は不要です。

## 5. シート (セクション 4 の各 zlib ブロック)

1 ブロックが Tfas の「シート」1 枚 (レイヤに近い概念で、シートごとに縮尺・単色指定・状態を持つ。新規図面の最初のシートは「ベース」)。ブロック内の先頭にシート情報レコードが並び、その後に図形が続きます。

| type | 内容 |
| --- | --- |
| 0x1004 | u32 独自縮尺フラグ, u32 縮尺分母, u8@8 表示, u8@10 編集可 (推定), u8@11 カレントシート, u8@12 単色指定 (色は 0x1005 の下位 8bit。カレントシートには適用しない), f64@128 シート基準高さ (mm), u8@136 階設定あり (1), @137 階名 (CP932, NUL 終端) |
| 0x1005 | u32 フラグ (下位 8bit = シートの単色指定の色、0x100 = グレー表示) + シート名 (CP932, NUL 終端) |
| 0x1006 | タグ付き: [[シート ID (u32×2), 種別, レイアウト ID (u32×2), モデル ID, ?, f64×12 (ビューポート), …, 表示シート名リスト / 非表示レイヤ名リスト, …]]。下記 |
| 0x1007 / 0x1008 | 外部参照 (外部リンク)。0x1008 は長さ付き文字列列: ディレクトリ, ファイル名, …, 参照するシート名 |
| 0x0002 / 0x0012 | エンティティ開始: u32 ID + u32 種別 (32bit 形式) / u64 ID + u64 種別 (64bit 形式) |
| 0x0003 | 図形本体: タグ付き [i32 長さ, 本体バイト列, i32, 拡張属性] |
| 0x0004 / 0x000C | エンティティ属性 (矢印・寸法設定、画像データなど) |
| 0x0005 | エンティティ終了 |

- 表示判定: byte8 が非 0、または byte11 (カレントシート) が非 0 (推定)。
- エンティティは入れ子になります。配管 (0x500 系)、ダクト、機器、寸法 (0x121/0x122)、引出し記号 (0x150/0x180150) などの複合オブジェクトは、表示用の基本図形を子として持っています。描画には末端の図形本体だけを使えば十分です。
- エンティティ種別の上位ビット 0x80000000 は補助図形、0x40000000 は非表示データ。

外部参照は、参照元ファイルの用紙範囲を参照先の用紙範囲に写像し、指定名のシートを取り込みます (縮尺の違う図枠ファイルでも一致することを確認)。

### レイアウトとビューポート

Tfas の「レイアウト」は、印刷用の別の用紙にモデルの一部を「ビューポート」で参照して配置するもの (Tfas の公式マニュアルのシート・レイアウトの解説)。

- 0x1006 の種別に 0x10000 が立つシートはレイアウトに属し、モデルには含まれない (0x10 はそのレイアウトのカレントシート)。
- レイアウト ID は u32 ペアを `hex(lo) + hex(hi)` (大文字 8 桁ずつ) にしたもので、セクション 24 の `<Layout id name/>` と一致する。
- f64×12 は [原点 xyz, U 軸 xyz, V 軸 xyz, 配置位置 xyz]。モデルの領域「原点 + s·U + t·V (s, t ∈ [0, 1])」が、レイアウト上の配置位置から U を +x、V を +y 方向として、文書縮尺 ÷ シート縮尺 倍で表示される。1/100 のビューポートでは U・V が回転していることがある。
- 後半のリスト: 先頭が数値のものは表示するモデルシート名 (「表示するシートを指定する」。無ければ全シート)、先頭がバイト列のものはビューポートで非表示にするレイヤ名。
- レイアウトの用紙サイズの格納場所は未確認 (ビューアはビューポートの配置範囲を用紙とみなす)。
- 初期表示は、カレントシート (0x1004 byte11) が属するレイアウト。

### 文字関数 (セクション 24)

```
<WordFunction>
  <Layout id="0123456789ABCDEF" name="(レイアウト名)"/> ...
  <WordFunction name="工事名称" value="(工事名)"/>
  <WordFunction name="図面名称" value=""><Layout id="..." value="(レイアウトごとの図面名)"/> ...</WordFunction>
</WordFunction>
```

文字の `$(工事名称)` などを値に置き換えて表示する。レイアウトごとの値があればそちらを使い、値が空なら `$(...)` のまま表示される。

## 6. 図形本体

共通ヘッダ 16 バイト:

| オフセット | 内容 |
| --- | --- |
| 0 | u32 種別。下位 16bit = 図形の種類、bit31 = 補助 (印刷しない)、bit30 = 非表示 (編集用データ。描画しない) |
| 4 | u32 図形属性 ID (上位バイト = 属性セット番号 \| 0x80) |
| 8 | u32 色番号 (bit31 = 継承) |
| 12 | u16 線種番号 (bit15 = 継承) |
| 14 | u16 線幅 (ペン) 番号 (bit15 = 継承) |

以降 f64 のモデル座標:

| 種類 | 内容 |
| --- | --- |
| 0x08 点 | x, y |
| 0x10 線分 | x0, y0, x1, y1 |
| 0x18 水平線 | y, x0, x1 |
| 0x20 垂直線 | x, y0, y1 |
| 0x28 / 0x30 | 垂直 / 水平の無限補助線 (x または y) |
| 0x38 / 0x39 ポリライン | u32 点数, u32 開閉 (0 = 閉じる, 1 = 開いたまま。0x39 は常に閉じる), (x, y)×点数 |
| 0x40 円 | cx, cy, r |
| 0x48 円弧 | cx, cy, r, 始点 x, y, 終点 x, y (始点から反時計回り) |
| 0x50 楕円 | cx, cy, rx, ry, 回転角 (度) |
| 0x58 楕円弧 | 楕円 + 始点 x, y, 終点 x, y |
| 0x60 スプライン | u32 点数, u32×3, 点ごとに x, y, 接線 tx, ty, 区間長 (f64) + 8 バイト。接線×区間長の Hermite 曲線 |
| 0x68 3D ポリライン | u32 点数, u32, (x, y, z)×点数 (配管の立体形状。通常は非表示データ) |
| 0x70 文字 | 下記 |

### 文字 (0x70)

| オフセット | 内容 |
| --- | --- |
| 16 | f64 x, y, 角度 (度), 文字高, 文字幅 (全角 1 文字), 未使用 |
| 64 | f64 行間 |
| 74 | u8 bit5: 1 = 寸法が実寸 (モデル単位)、0 = 用紙 mm (表示時に文書縮尺を掛ける) |
| 76 | u8 幅率 (%) |
| 78 | u8 下位 4bit: 配置 |
| 79 | フォント名 (CP932, NUL 終端, 空なら既定) |
| 続き | 本文 (CP932, NUL 終端、行は `\n` 区切り) |

配置コード: 1 左下, 2 中下, 3 右下, 8 左中, 4 中中, 9 右中, 5 左上, 6 中上, 7 右上 (表のセル内文字の統計から確定)。半角文字の幅は全角の半分。行送りは文字高 + 行間 (プレビュー画像の文字枠で確認)。

## 7. レイヤ (図形属性表) と線種

Tfas の「レイヤ」はこの属性表に格納されている (ID の上位バイトのセット番号 + 1 がレイヤグループ: 1 基本, 2 建築, 4 電気, 5 空調, 6 衛生)。図形本体の属性 ID がどのレイヤに属するかを示す。セクション 1 の zlib ブロック内レコード 0x1001 (先頭 8 バイトの後がタグ付き値) に、セットごとのリストがあります。各エントリ:

```
[ u32 ID (上位バイト = セット番号 | 0x80),
  [ .., .., .., 名前 ],
  [ モード, u32 色, …, u16 線種, (線種定義), u16 線幅, … ],
  … ]
```

DWG 由来の属性 (線種や用途をローマ字で名付けたもの) には、線種を最初に使うエントリに線種定義が埋め込まれています: f64@16 単位係数, @28 名前, f32@96 1 周期の長さ, u16@110 要素数+1, @160 から 8 バイトおきに f32 の累積位置 (正 = 実線区間の終端、負 = 空白区間の終端)。周期長 ÷ 単位係数 が用紙 mm になります。

### レイヤ表のエントリ

各エントリは `[u32 ID, [名称…], [モード, u32 色, …, u16 線種, …, u16 線幅, …], [並び順], 末尾の値]`。末尾の値は通常 0 で、外部参照・DWG から取り込んだレイヤ (`図枠ファイル名|レイヤ名` の形の名前や、AutoCAD 標準の `0`・`Defpoints` など) では 1〜3 になる。公式マニュアル付属の完成図では末尾が 1 のレイヤ (柱・壁・通り芯) が内蔵プレビューに描かれているため、表示・非表示のフラグではない (取り込み元を表すと推定)。レイヤの表示状態の格納場所は未特定。

## 8. 色

色番号 → RGB (Tfas 内部のパレット。プレビュー画像との照合で推定):

- 1 白, 2 #5B5B5B, 3 赤, 4 緑, 5 青, 6 黄, 7 マゼンタ, 8 シアン, 15 #C0C0C0, 16 #808080, 17 #C6C6C6
- 9〜14, 30 は AutoCAD ACI の 222, 42, 30, 103, 150, 190, 214
- 31 以降は ACI 10〜255 から上記 7 色を除いた順 (例: 31 = ACI10, 60 = ACI40, 152 = ACI134, 244 = ACI230)

表示色の決定 (プレビューとの画素一致率 92%):

1. シートのフラグ 0x100 → グレー表示 (マニュアルに対応する項目は見当たらない。推定)
2. シートの単色指定 (0x1004 byte12) → その色の単色表示。ただしカレントシートは図形色 (公式マニュアルの FAQ)
3. 図形の色が継承 (bit31) → シートの色 (属性セット 0 = 基本グループはレイヤの色)
4. それ以外 → 図形の色

以前は「属性セット 0, 1, 5 はレイヤの色」としていたが、マニュアルの分割枠の例 (白のレイヤに赤で作図) とプレビュー統計で否定された。

## 9. 線幅・線種

- 線幅番号: プレビューでは 13 以上が太く、20 番台はさらに太く描かれる (推定)。
- 組込線種: 公式マニュアル (シート・レイアウトの解説) の付録に 1〜98 の見本がある。見本から測った比率 (線:空白…) で、2 と 4 の周期を 4 mm として換算して描く。
  - 2 破線 73:23 / 3 細破線 12:12 / 4 一点鎖線 37:23:13:23 / 5 二点鎖線 / 6 破線 70:18 / 7 粗い破線 70:70 / 8〜10 長線 + 点 1〜3 個 / 11 点線 / 12・13 長線 + 短線 / 14 破線 + 点 / 20〜26, 33〜39 (細かい刻み)
  - 29〜32, 59〜61 は二重線、27・28 は「×」入り、74〜79 は波線 (未対応、実線で描く)
- 線幅: 印刷線幅の候補は 通常 / 0.1〜0.9 / 1.0 / 1.5 / 2 / 3 / 5 / 7 mm (公式マニュアルの FAQ)。線幅番号 16 = 3.0 mm を確認。

## 10. 画像・OLE

- 種別 0x165: ラスタ画像。属性レコード (0x0004) に `u32 2 + ファイル名` と `u32 形式 + データ` (0 = BITMAPINFOHEADER から始まる DIB、1 = JPEG。PNG は署名で判別)。図形本体の 4 点ポリライン (補助) が配置位置で、左下・右下・右上・左上の順。
- 種別 0x160: OLE 埋め込みオブジェクト。図形本体の 4 点ポリライン (補助) が配置枠で、こちらは左下・左上・右上・右下の順。レコード 0x0007 は 24 バイトの Tfas ヘッダ (u32 0x100, u32 連番, …) の後に OLE 複合ドキュメント (CFB, `d0 cf 11 e0`) が続く。表示に使うデータ:
  - `CONTENTS`: 静的な図 ("Picture (Enhanced Metafile)" など)。u32 の後に EMF。
  - `\x02OlePres000`: 表示キャッシュ。クリップボード形式 (CF_DIB = 8 / CF_METAFILEPICT = 3 は WMF / CF_ENHMETAFILE = 14) + ターゲットデバイス + 縦横 (0.01 mm) + データ。
  - `\x01Ole10Native`: OLE1 ネイティブ。パッケージ (埋め込みファイル) はラベル・元パス・一時パス・データの順。表示データはない。
  - サンプルの図はいずれも画像を貼り付けたもので、EMF/WMF の中身は `STRETCHDIBITS` などのビットマップ転送のみ (マスク画像との OR / AND による透過を含む)。ビューアはこれらを 1 枚の RGBA 画像に合成して表示する。線・文字のベクタ命令は未対応。
- Tfas は画像・OLE の外周に灰色 (#808080) の 1 ピクセル枠を描く (プレビューで確認)。

## 11. エンティティ種別 (複合オブジェクト)

レコード 0x0002 / 0x0012 の種別のうち、トップレベルで観測したもの (下位 12 ビット。0x40000 / 0x80000 / 0x100000 はフラグと推定):

| 種別 | 内容 (使用図面と中身からの推定を含む) |
| --- | --- |
| 0x08〜0x70 | 単独の基本図形 (点・線・連続線・円・円弧・楕円・文字…) |
| 0x170 | 複合図形 (器具・枠付き文字など。推定)。文字データを持たないもの (壁などの図形) もある |
| 0x120 | 部品・シンボル (部品ライブラリから配置したもの。子に 0x540 接続口) |
| 0x121 / 0x122 | 寸法 / 寸法線 |
| 0x12a | 角度寸法 |
| 0x130 / 0x131 | ハッチング類 (推定) |
| 0x150 | グループ (配管サイズ表記などの引出し記号のほか、IFC から取り込んだ 3D 図形 = 子 0x190 の 3 次元折れ線もこの中) |
| 0x160 / 0x165 | OLE / ラスタ画像 |
| 0x1a1 | 引出線付き注記 |
| 0x200 系 | 建築部材: 0x201 柱、0x205 壁、0x207 梁、0x20a 床 (スラブ)、0x20b 天井 (サンプルの IFC の IfcColumn / IfcBeam / IfcSlab と個数・位置が一致)。0x203 / 0x209 / 0x20c は未特定 |
| 0x400 / 0x460 / 0x470 | 電気設備 (配線・記号・器具。推定。0x470 は配置座標系を持つ) |
| 0x480 | 設備 (配管と同じ属性を持つ。フレキなど) |
| 0x500 | 空調設備 (ダクト・配管。子に 0x502 / 0x503 / 0x508 / 0x5f0) |
| 0x550 / 0x650 | 機器 (推定) |
| 0x600 | 衛生設備 (配管) |

## 12. 部品ライブラリ (サブセットライブラリ)

Tfas の「サブセットライブラリのインポート処理」で読み込む部品データフォルダー。2 種類ある。

- メーカー部品 (`<メーカー>_buhin_All` のような名前のフォルダー): `xxxNNNNN.NCP` (図形) + `.MDB` (一覧・仕様)。電気設備用は `.USR` も付く。
- カスタムデスク (`<会社名>_buhin_CustomDesk` のような名前のフォルダー): `.MDB` + `.USR` のみ。各部品は Tfas 本体のストック部品 (`ストックキーコード(デスク用)`) を参照し、形状は Tfas が生成するため、ファイルには図形がない。表示できるのは `イメージテーブル` の EMF アイコン (100×100) だけ。

### NCP

| オフセット | 内容 |
| --- | --- |
| 0x00 | `"TFAS"` |
| 0x40 | u32 ファイルサイズ, u32 使用エントリ数, u32 索引容量 (2048 / 1024), u32 索引オフセット (0x58), u32 データ開始, u32 データサイズ |
| 索引 | 208 バイト × 容量。+0 コード (24 バイト), +0x18 名称 (CP932, 40 バイト), +0x43 日付 yyyymmdd, +0xa4 u32 縮尺, +0xc8 u32 データ内オフセット, +0xcc u32 サイズ |

- コードは `[設備][ビュー番号][分類3文字]$2?[呼出しコード]` (例 `A06D1$2XXXXXXXX`。`XXXXXXXX` はメーカーの型番など)。ビュー番号 0 平面 / 1 正面 / 2 背面 / 3 右側面 / 4 左側面。MDB の部品コードはビュー 0 のもの。
- 各エントリは .tfs のシートブロックと同じレコード列 (非圧縮・8 バイト境界)。部品エンティティ (0x100120 / 0x140120) の下に、属性 0x180 名称・0x515 長い名称・0x10531 3D モデル、図形、0x540 接続口が並ぶ。
- 3D モデルは平面ビューの属性 0x10531 にある "DecTop" 形式の境界表現 (BODY/SHEL/FACE/COED/EDGE/VRTX)。中身は三角形メッシュで、外形は平面図と一致する。

### MDB / USR (Jet 4 データベース)

| テーブル | 内容 |
| --- | --- |
| `ｻﾌﾞｾｯﾄ` | レコード区分 0 ライブラリ名、1/2/3 大・中・小分類 (分類コード１〜３)、4 部品 (部品コード(機能), 呼出しコード = 型番, 名称, 表示用ＳＱ №, ストックキーコード(デスク用)) |
| `型式名称` | 部品コード → 長い名称 |
| `仕様属性` | 部品コード, 項目 GID/ID, 拡張 GID/ID 1〜6, 単位, 値 (能力・寸法など。項目名はファイルになく値から推定) |
| `イメージテーブル` | 部品コード (各ビュー) → EMF プレビュー |
| `Attr` | 電気設備の属性 (配線引出区分・取付区分・材料拾い区分・負荷容量など) |

## 13. 3D データ

Tfas の 3D 表示・断面表示は、図面に保存された以下のデータから作られる (3D モデル自体は保存されていない)。いずれも複合オブジェクト直下の非表示 (0x40000000) の 3D ポリライン (0x68) と属性 (0x0004) にある。座標はシート内の値で、表示時にシート基準高さ (0x1004 @128) を足す。

図面の縮尺と違う縮尺のシート (0x1004 の u32@0 = 1 のとき u32@4 がシート縮尺。例: 1/50 の図面の 1/10 詳細図) では、座標・高さが実寸の (図面縮尺 ÷ シート縮尺) 倍で入っている。例: 1/50 の図面の 1/10 シートでは、注記「FL+2750」の配管が z = 13750。属性に入っている寸法 (呼び径・ダクト寸法・0x512 など) は実寸 (mm) なので、3D にするときは同じ倍率を掛ける。弁の寸法 (下記) を全図面で比べると、倍率 1・1.667・5 のシートで同じ値になる (例: ZVLVGB10IS 20A は L1 32.5 / H1 175 / ハンドル径 80 / 接続口 40)。

### 配管・ダクト (0x500 / 0x600 / 0x480)

- 3D ポリラインが芯線。直管・直ダクト (属性 0x504 の f64 長さ > 0) は経路の点列。継手・バルブ・制気口など (長さ 0) は「中心点、各接続口の点…」。
- 角ダクトは、中心から W/2 または H/2 離れた、芯線に直交する点を追加で持ち、断面の向き (幅または高さの方向) を表す。立てダクトの向きはこの点で決まる。
- 継手の点列には中心点が繰り返し現れることがある (例 `中心, 端1, 中心, 端2, 中心, 向き`)。

| 属性 | 内容 |
| --- | --- |
| 0x503 | 部材コード (CP932 10 文字)。`PIPE…` 直管、`J…` 継手、`Z…` バルブ類、`DSP…` スパイラルダクト (丸)、`DFL…` フレキダクト (丸)、`DDC…` 角ダクト、`DSN…` 制気口、`SLE…` スリーブ など |
| 0x504 | f64 長さ (直管)、以降 f64 -1 ×3, 係数… |
| 0x50a | ダクト寸法: u16@8 幅, u16@10 高さ (mm)。後半に変径後の寸法 |
| 0x50b | 配管の呼び径: u16@6 (A) |
| 0x516 | 冷媒管 (2 本組) の寸法。未解読 (表示は平面図の幅から) |
| 0x517 | スリーブ径: u16@0 |
| 0x512 | ダクト機器の寸法: i32×3 = W, D, H (消音チャンバー・ボックスなど) |

#### バルブ (コード `ZVLV…`)

Tfas のバルブの寸法項目 (公式マニュアルの出力データ形式の解説と、ユーザー部材の登録項目) は 口径・D1 (接続口外径)・L1 / L2 (芯から接続口までの長さ)・H1 (ハンドル高さ)・H2 (ハンドル径)。図面では次のように入っている (サンプル 280 図面のバルブ 2,094 個すべてで同じ構造)。

- 3D ポリライン 4 点 `[中心, 接続口 1, 接続口 2, ハンドル先端]` → L1, L2, H1 と弁棒の向き。
- 子 0x508 (非表示) に平面上の外形 (0x38 折れ線) が 3 つ。属性 0x515 の (u32 番号, u32 役割)×n が役割を示す: 0x10 接続口 1、0x11 接続口 2、0x20 ハンドル (0x21 が加わるものもある)。接続口の外形は端面を上から見た線 (立て管では多角形) で、幅が D1。ハンドルの外形はハンドル円に外接する多角形 (弁棒が鉛直のとき) または端面を見た線で、幅が H2。
- 子 0x503 (中心線) があるものは実寸。ないものの多く (1,137 個) は単線表示の記号の寸法で、外形の幅がすべて記号の大きさ S に等しく L1 = 0.75 S (仕切弁は H1 = 1.804 S)。
- 弁本体の形 (接続口の間) は仕様にも図面にもない。

#### ダクト機器 (`DSNTSYO…` 消音チャンバー、`DSNTBOX…` ボックス)

0x512 = W, D, H、3D ポリライン `[中心, 中心 + 幅方向 W/2, 中心 + 高さ方向 H/2]` (サンプル 19 個すべて)。奥行き D は残りの方向。他の `DSNT…` (形鋼・ボルト・基礎・ガラリなど) は形式がそろわず未解読。

### 建築部材 (0x2xx)

3D ポリラインは `[基準点, 基準点 + 押出し, 外形の頂点…]`。外形を (点1 − 点0) 方向に押し出した角柱が部材の形。柱・壁は基準点が中心 (外形の内側または辺上)、床・天井のように頂点で入力した外形では基準点が最初の頂点を兼ねる (このとき基準点は残りの頂点の外側にある)。押出しは通常は鉛直 (柱: 上端→下端、梁・スラブ: 上端から下へ梁成・スラブ厚) だが、断面図として描かれた部材では水平になる。勾配スラブは外形の z が頂点ごとに異なる。

例 (サンプル図面の 1F の柱): `(30500, 18400, 4000), (30500, 18400, 0), (30900, 18400, 4000), (30900, 18800, 4000), (30100, 18800, 4000), (30100, 18000, 4000), (30900, 18000, 4000)` → 800×800、高さ 0〜4000。同じ建物の IFC の IfcColumn (位置 (30500, 18400, 0)、押出し 4000) と一致。

### 部品・器具 (0x120 / 0x170 / 0x470)

4 点の 3D ポリライン `[原点, 原点 + X 軸, 原点 + Y 軸, 原点 + Z 軸]` が配置座標系 (原点の z が取付高さ)。立体形状は部品ライブラリ (NCP の DecTop) 側にあり図面にはない (配置部品 6,219 個に 0x10531 は 0 個)。接続口は下記の 0x540。

- **軸の長さ 128 が倍率 1**。図面のセクション 3 には配置した部品の定義 (5 面図: コード 2 文字目が 0 平面・1 正面・2 背面・3 右側面・4 左側面。レコード 9 で始まり、属性 0 がコード) が実寸の 2D で入っており、配置された図形は「定義の図 × 軸の長さ ÷ 128」(軸ごと) になる。サンプル 280 図面で、空調・衛生の部品 (コード `A…` `S…`) は 7,900 / 8,321 が一致 (メーカー部品は 299 / 299)。不一致は配置側に線が足されたもの・原点がずれたもの。電気の部品 (`E…`) は 3,484 / 6,579 しか一致せず (多くは 2/3 倍)、別の倍率がある。128 という値の由来は不明 (資料に記載なし)。最多は 128/128/128 (7,012 個)。
- **0x506** = f64×6 `[W, D, H, 最小 x, 最小 y, 最小 z]` (部品の単位)。部品の 3D 外形の箱とみられる: 部品定義 343 件で、この箱は平面図の範囲の内側に 343 件すべてが収まり、206 件は一致する。正面図の範囲の内側に収まるのは 211 / 224 件。一致しないのは図に点検スペースなど本体以外も描かれているもの。
- 0x446 の先頭の f64×3 が幅・奥行き・高さ (電気部品。平面の外形と一致する場合)。
- 0x506 も 0x446 もない部品 (`%` 付きの汎用記号など 2,522 個) は高さの情報がない。
- 5 面図と部品の軸の対応: 平面図 = (x, y)、正面図 = (x, z)、背面図 = (−x, z)、右側面図 = (y, z)、左側面図 = (−y, z)。0x506 の箱と各図の範囲を比べ、範囲が原点に対して非対称で向きを判定できるものを数えた (サンプル 280 図面の部品定義 156 種): 正面図の横 そのまま 15・反転 0、背面図 反転 18・そのまま 0、右側面図の横 = y そのまま 28・反転 0、左側面図 反転 22・そのまま 0、各図の縦 = z そのまま 76〜81・反転 0。どちらとも合わないもの (正面図の横で 13 など) は、図に本体以外の線が描かれていて範囲が箱と一致しないもの。ビューアはこの対応で 5 面図の外形を押し出して重ね、部品の形を推定する (`src/tfas/partviews.ts`)。

#### 接続口 (0x540)

Tfas の機器・器具の接続口は、公式マニュアルの出力データ形式の解説 (機器・器具の出力) では接続口ごとに 用途・サイズ・座標・接続 (接続している図形の系統番号) を持つ。図面では部品の子エンティティ 0x540 にある。サンプル 280 図面では配置部品 61,323 個のうち 4,335 個が計 10,550 個の接続口を持つ (部品あたり 1 個 764・2 個 2,382・3 個 149・4 個 903・5 個以上 137)。

- 非表示の 3D ポリライン 2 点 `[部品側の点, 接続点]` と補助点 (0x08) を持つ。接続点が配管・ダクトのつながる位置。
- 0x531 (3,180 個) / 0x540 (634 個): u32 = 接続している配管 (0x600) またはダクト (0x500) の図形 ID。3,814 個のうち 3,793 個の ID が同じシートにあり、その 3,793 個すべてで相手の芯線の端点が接続点から 1mm 以内にある。0x531 と 0x540 の違いは不明。
- 0x533 (113 個): u32 = 別のシートの図形 ID (113 個すべてが図面内の別シートにある)。シート間接続とみられる。
- 参照を持たない接続口は 6,623 個。そのうち接続点に配管・ダクトの端点があるのは 198 個だけで、残りは何もつながっていない。
- 0x530 (全接続口): u16×8。3 番目の値は、つながっている配管の呼び径と 594 / 843 件で一致する。用途などほかの値は未解読。

### 取り込んだ 3D 図形

IFC インポートで部材化されない要素 (IfcBuildingElementProxy・窓・扉など) は、グループ (0x150) の下に表示属性の 3D ポリラインとして入る。始点と終点が一致するものは面の輪郭 (4 点 + 閉じ点の四角形が多い)。
